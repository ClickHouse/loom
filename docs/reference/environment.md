# Environment variables reference

Almost everything Loom is configured with is a settings field: the
environment variable `LOOM_<FIELD>` of a field on `server.settings.Settings`,
listed with its default and meaning in the generated
[configuration reference](./configuration.md). This page covers the rest: the
variables read directly with `os.environ` (or a shell `${VAR}`) by the server,
the CLI, the SDKs, the plugins, the container image, the compose files and the operator
scripts. The `LOOM_*` ones are listed in `NON_SETTINGS_ENV` (`server/settings/_env.py`),
or, for a family such as the webhook signing secrets, in `NON_SETTINGS_ENV_PREFIXES`, and
the server's unknown-variable warning skips them;
`tests/unit/test_environment_reference.py` keeps those lists and this page the same.

| `NODE_OPTIONS`                                       | `server/code/workers/scip_ts_delta.py`, `scip_py_delta.py` | unset                | Passed through to the compiler-tier indexer subprocess; every other variable of that subprocess is set by the worker.                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `SCIP_ENV_JSON`                                      | `server/code/workers/scip_py_delta.py`                     | unset                | Passed through to the Python compiler-tier indexer.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `PATH`                                               | `server/code/workers/scip_go_delta.py`                     | inherited            | Searched for the Go toolchain and indexer binaries; the subprocess gets its own `PATH`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `LOOM_WEBHOOK_SECRET_<ORG>__<NAME>`                  | `server/core/webhooks.py`                                  | unset                | A webhook signing secret, named by a memory webhook's `secret_ref` or a task inbox's `webhook_secret_ref`; ORG is the org id encoded as in [task inbox webhooks](../features/tasks-and-decisions.md). Unset, a `whsec_` value that is empty or not base64, or a value that is not UTF-8, the secret is not usable: memory webhook events wait (dead after 2.5 days) and a task inbox's notices are held; the server warns once, naming the variable. `LOOM_LLM_MODEL`) is settings; see
[Deployment](../operations/deployment.md#providers) and

## Container image and uvicorn

Read by `scripts/serve.sh`, the image's command, which starts uvicorn. It takes
them from its environment only, not from `.env` or `LOOM_ENV_FILE` (compose's
`env_file:` sets them in the environment), except the settings fields
`LOOM_WEB_WORKERS`, `LOOM_TRUSTED_PROXIES` and `LOOM_RUNTIME_DIR`, which it
resolves as the server loads them: the environment, then the env file, then the
[settings file](configuration.md):

| Variable                   | Default              | Meaning                                                                                                                                                                                                                                                                                                                                                |
| -------------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `PORT`                     | `7777`               | The port uvicorn binds inside the container.                                                                                                                                                                                                                                                                                                           |
| `LOOM_LISTEN_HOST`         | `127.0.0.1`          | `uvicorn --host`: the address it listens on. The image sets `0.0.0.0`; `LOOM_BIND_HOST` stays the address the startup checks read, and `scripts/serve.sh` sets it to a non-loopback listen address when the environment does not set it (overriding an env-file or settings-file value).                                                               |
| `LOOM_WEB_WORKERS`         | one per CPU, up to 8 | `uvicorn --workers`. Unset, one per CPU the container may use (its cpuset, lowered by a CPU quota), at most one per GiB of memory and at most 8. The compose files set it unless `.env` names a count: 2 in `deploy/standalone` and the dev stack, 1 in the cloud and colour stacks. Also a settings field, which the rate limiter divides budgets by. |
| `LOOM_UVICORN_LOOP`        | `asyncio`            | `uvicorn --loop`: `asyncio`, `auto` or `uvloop`. uvloop forks the whole process for each git spawn, which stalls its loop.                                                                                                                                                                                                                             |
| `LOOM_TRUSTED_PROXIES`     | `127.0.0.1`          | `uvicorn --forwarded-allow-ips`: the peers whose `X-Forwarded-For`/`-Proto` are applied.                                                                                                                                                                                                                                                               |
| `LOOM_GRACEFUL_SHUTDOWN_S` | `10`                 | `uvicorn --timeout-graceful-shutdown`: how long a stopping process drains requests.                                                                                                                                                                                                                                                                    |
| `LOOM_KEEP_ALIVE_S`        | `5`                  | `uvicorn --timeout-keep-alive`: how long an idle connection stays open. Behind a load balancer that reuses connections, longer than its idle timeout.                                                                                                                                                                                                  |

Build argument: `LOOM_BUILD_COMMIT` (baked into the image as `LOOM_BUILD_COMMIT`,
reported as `build_commit`). The image always carries the local CPU embedder and its
default model, and sets `LOOM_LOCAL_EMBEDDING_MODEL_DIR=/app/models`. The remaining
`ARG`s pin toolchain versions and checksums for the compiler-tier indexers
(`GO_VERSION`, `NODE_VERSION`, `SCIP_GO_VERSION`, `SCIP_CLANG_VERSION`, their
`*_SHA256*` values and `LLVM_SIGNER_FPR`, the LLVM signing key);
`scripts/install-code-toolchains.sh` pins the tools it installs with npm
(scip-typescript, scip-python and the package managers).

## Compose files

| Variable                                        | Read by                                                    | Default                               | Meaning                                                                                                                                       |
| ----------------------------------------------- | ---------------------------------------------------------- | ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `LOOM_CH_HOST_PORT`, `LOOM_CH_NATIVE_HOST_PORT` | `dev/docker-compose.dev.yml`, `dev/ci_start_clickhouse.sh` | `8123`, `9000`                        | Host ports the local ClickHouse publishes (HTTP and native).                                                                                  |
| `LOOM_CH_CONTAINER`                             | `dev/ci_start_clickhouse.sh`                               | `loom-ch`                             | Container name, so a second ClickHouse (one per worktree) runs beside the first.                                                              |
| `LOOM_COLOUR`, `LOOM_COLOUR_PORT`               | `dev/docker-compose.colour.yml`                            | required                              | Which colour (`blue` or `green`) and host port (`7781` or `7782`) a blue/green project runs.                                                  |
| `LOOM_CLICKHOUSE_IMAGE`                         | `compose.yaml`, `dev/ci_start_clickhouse.sh`               | `clickhouse/clickhouse-server:latest` | The ClickHouse image the stack runs. A release bundle's compose file defaults it to the release the bundle was built and schema-checked with. |
| `LOOM_IMAGE_REPOSITORY`, `LOOM_VERSION`         | `compose.yaml`, `install.sh`                               | `ghcr.io/clickhouse/loom`, `latest`   | The image and tag the standalone stack runs; the installer pins the tag in `.env`.                                                            |
| `LOOM_EXTRACTOR_IMAGE_REPOSITORY`               | `compose.yaml`, `install.sh`                               | `ghcr.io/clickhouse/loom-extractor`   | The document extractor service's image, run at `LOOM_VERSION`.                                                                                |
| `LOOM_PORT`                                     | `compose.yaml`, `install.sh`                               | `7777`                                | The host port the standalone stack publishes.                                                                                                 |
| `LOOM_REPOSITORY`                               | `install.sh`                                               | `ClickHouse/loom`                     | The GitHub repository whose releases the installer downloads.                                                                                 |
| `LOOM_RELEASES_URL`                             | `install.sh`                                               | GitHub                                | Where the installer downloads release files, an `https://` URL; by default `https://github.com/$LOOM_REPOSITORY/releases`.                    |

Given to the installer, `LOOM_VERSION` installs the release it names. Without it, a release's
`install.sh` installs its own release and the repository's copy installs `latest`; an older
release over a newer install is refused unless `LOOM_VERSION` names it
(pin ClickHouse first:
[downgrading an installer install](../operations/upgrades.md#downgrading-an-installer-install)).

Other `${LOOM_*}` references in the compose files are settings fields given a
compose-level default and the uvicorn variables above. The installer keeps the two image
repositories (`LOOM_IMAGE_REPOSITORY`, `LOOM_EXTRACTOR_IMAGE_REPOSITORY`), the tag, the
port, the bind host and `LOOM_CLICKHOUSE_IMAGE` in `.env` when given; the
[quickstart](../getting-started/quickstart.md) describes what the stock `.env` sets.

| `LOOM_API_KEY_FILE`                | `server/cli/_client.py`, the plugins' `lib/loom-client.mjs`, the grep shim | `~/.loom/token`             | The token file read when `LOOM_API_KEY` is unset.                             |

## SDKs

| Variable            | Read by                    | Default                                        | Meaning                                                                                          |
| ------------------- | -------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `LOOM_BASE_URL`     | Python and TypeScript SDKs | `http://localhost:7777`                        | The server, when the constructor gives none.                                                     |
| `LOOM_API_KEY`      | Python and TypeScript SDKs | the `loom login` session, then `~/.loom/token` | The bearer token, when the constructor gives none. Blank counts as unset.                        |
| `LOOM_PROFILE`      | Python and TypeScript SDKs | `default`                                      | The `loom login` session in `~/.loom/credentials` a client uses when the constructor names none. |
| `LOOM_LOG_LEVEL`    | Python and TypeScript SDKs | unset                                          | The SDK logger's level (`debug`, `info`, `warning`/`warn`, `error`, `off`).                      |
| `LOOM_MENTOR_BRIEF` | Python and TypeScript SDKs | off                                            | `on` fetches `mentor.brief` in the background on the first call.                                 |
| `LOOM_AUTO_RUN`     | Python SDK                 | off                                            | Bind an ambient run to each `Agent`'s lifetime.                                                  |

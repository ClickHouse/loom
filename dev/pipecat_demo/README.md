# Text memory recording

The optional `pipecat-demo.yml` workflow records one real text turn against an isolated, auth-on server with fake LLM and embedding providers. It checks out the qualified source commit named in the workflow and installs Pipecat 1.16.0. It creates a fresh application family and uses synthetic preference text. It calls the example's Python `main()` entrypoint; it does not demonstrate a separate CLI process, resumed or protected-family restore, audio, or interruptions.

The filming case retains every assertion in the native qualification case. After those assertions pass, it exports only the matched synthetic preference and the two observed persisted role/content pairs. The browser receives allowlisted process status and those validated observations. Original native diagnostics reach the job log. The video labels the observations as post-run results and labels its reading hold explicitly.

Dispatch the workflow on `main` with `expected_sha` equal to the exact merged commit. It refuses other refs, changed fixture files, reused receipt paths, missing runner tools, and occupied server ports. Server readiness must belong to its exact owned process group before health probes or native work. Every driver HTTP request checks its exact owned listener, including session creation and cleanup. MediaInfo runs as a registered child with bounded communication; its group anchor remains unreaped until cleanup. One Python owner defers cancellation across each child launch and registration. It retains unreaped group leaders as identity anchors until live descendants stop, then reaps the owned children. Chrome runs as a normal user with its sandbox intact. There is no local-execution mode or renderer installation fallback.

The workflow uploads a **public** artifact containing the WebM, sanitized receipt, and recording status for seven days. It uploads no browser profile, server log, session pointer, or credential file. GitHub job logs retain the normal native output. Review the actual video for legibility and accurate content before linking it as a demonstration. A passing native result without a qualified capture is not a completed video.

The recording workload has its own execution budget and fresh evidence path. It does not change the mandatory native qualification step, its assertions, timeout, upload, or isolation checks, and it is not a release gate.

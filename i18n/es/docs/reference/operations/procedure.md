# Operaciones de `procedure`

Los campos exactos que recibe y devuelve cada operación `procedure.*`.

<!-- Generated by `python scripts/codegen/docs_reference.py` from the op registry; edit the models, not this page. -->

Cada op es `POST /v1/<op>` sobre HTTP y la herramienta MCP `loom_<op>`. Los campos de identidad (`org`, `namespace`, `agent`, `user_id`, `session_id`) se completan a partir del token y de la sesión MCP cuando el transporte puede hacerlo; en una llamada HTTP sin token en un servidor de un solo usuario, se completa con la org de la instalación en todas las ops excepto `code.*` y `tracker.*` (que conservan la de su plano), y en [algunas ops](https://github.com/ClickHouse/loom/blob/main/docs/reference/http-api.md#request) también su espacio de nombres y su agente; consulta [identidades y espacios de nombres](https://github.com/ClickHouse/loom/blob/main/docs/concepts/identities-and-namespaces.md). El [índice de operaciones](https://github.com/ClickHouse/loom/blob/main/docs/reference/operations.md) explica el rol, el tipo y el listado `all` de MCP. Los campos de entrada desconocidos se atienden y se nombran en `ignored_args`.

## `procedure.add`

Registra una memoria procedimental: una receta de tipo "cómo hacer X" con campos estructurados (name, situation, steps).

`POST /v1/procedure.add` · MCP `loom_procedure_add` · rol `writer` · escritura

| Campo de entrada | Tipo | Valor por defecto | Significado |
| --- | --- | --- | --- |
| `org` | `str` | obligatorio | El tenant (primer elemento de la tupla de identidad). |
| `namespace` | `str` | obligatorio | El espacio de nombres que la op lee o escribe. |
| `agent` | `str` | `'-'` | El agente que escribe o lee; `'-'` o `'*'` significa cualquier agente cuando la op lo permite. |
| `user_id` | `str` | `'-'` | El usuario final al que pertenece la fila; `'-'` si no hay ninguno. |
| `session_id` | `str` | `'-'` | La sesión o conversación a la que pertenece la fila; `'-'` si no hay ninguna. |
| `name` | `str` | obligatorio | Nombre del procedimiento; la clave de la memoria es `procedure_<slug of name>`, por lo que el mismo nombre la reescribe. |
| `situation` | `str` | obligatorio | Cuándo se aplica el procedimiento (su precondición); este texto determina `procedure.match`. |
| `steps` | `list[str]` | obligatorio | Al menos dos: un único paso es una lección, no un procedimiento (el minero aplica la misma regla). |
| `tags` | `list[str]` | *(calculado)* | Etiquetas del llamador almacenadas en el procedimiento; la fila también recibe la etiqueta `procedure`. |
| `metadata` | `dict[str, Any]` | *(calculado)* | Metadatos estructurados opcionales (precondiciones como clave-valor, salidas esperadas, ...). |
| `graph` | `dict[str, Any] \| None` | `None` | Grafo ejecutable opcional (nodos = pasos / memoria / consolidación / decisión, aristas = dep / dataflow / branch). |

| Campo de salida | Tipo | Significado |
| --- | --- | --- |
| `memory_key` | `str` | Clave de la fila del procedimiento (`procedure_<slug>`). |

## `procedure.evolve`

Consolida las trazas de ejecución acumuladas de un procedimiento en un grafo mejorado: clasifica el camino probado según los recorridos EXITOSOS, marca como callejones sin salida los pasos que ninguna ejecución usó, y marca los pasos y transiciones que se encuentran…

`POST /v1/procedure.evolve` · MCP `loom_procedure_evolve` · rol `writer` · escritura · no figura en el toolset `all` de MCP

| Campo de entrada | Tipo | Valor por defecto | Significado |
| --- | --- | --- | --- |
| `org` | `str` | obligatorio | El tenant (primer elemento de la tupla de identidad). |
| `namespace` | `str` | obligatorio | El espacio de nombres que la op lee o escribe. |
| `agent` | `str` | `'-'` | El agente que escribe o lee; `'-'` o `'*'` significa cualquier agente donde la op lo permita. |
| `user_id` | `str` | `'-'` | El usuario final al que pertenece la fila; `'-'` si ninguno. |
| `session_id` | `str` | `'-'` | La sesión o conversación a la que pertenece la fila; `'-'` si ninguna. |
| `memory_key` | `str` | obligatorio | Clave del procedimiento que se va a evolucionar (`procedure_<slug>`). |
| `min_runs` | `int` | `3` | Número mínimo de ejecuciones incorporadas antes de que la poda actúe sobre la evidencia. |
| `gate_mode` | `Literal['sprt', 'margin']` | `'sprt'` | Puerta de aceptación para una revisión pendiente. |
| `gate_min_runs` | `int` | `3` | Ejecuciones necesarias sobre la revisión en prueba antes de cualquier veredicto. |
| `gate_margin` | `float` | `0.05` | modo margin: la caída de la tasa de éxito que provoca una reversión. |
| `gate_min_drop` | `float` | `0.15` | modo sprt: la caída por la que vale la pena revertir, las tasas de error, y el número de ejecuciones a partir del cual decide la estimación puntual. |
| `gate_alpha` | `float` | `0.05` | modo sprt: tasa de error de falsa reversión; un valor menor requiere más evidencia antes de revertir. |
| `gate_beta` | `float` | `0.2` | modo sprt: tasa de error de caída no detectada; un valor menor requiere más evidencia antes de aceptar. |
| `gate_max_runs` | `int` | `50` | modo sprt: ejecuciones sobre la revisión a partir de las cuales decide la estimación puntual. |
| `strike_limit` | `int \| None` | `None` | Ejecuciones fallidas consecutivas que ponen el procedimiento en cuarentena; None = LOOM_PROCEDURE_STRIKE_LIMIT (3), 0 = nunca. |

| `gate_cost_min_samples` | `int \| None` | `None` | Ejecuciones exitosas con costo que necesita cada lado para la comprobación de costo; `None` = `gate_min_runs`. |

| Campo de salida | Tipo | Significado |
| --- | --- | --- |
| `memory_key` | `str` | Clave del procedimiento evolucionado. |
| `version` | `int` | Versión de la fila del procedimiento que escribió esta llamada. |
| `revision` | `int` | La revisión de topología del procedimiento tras esta llamada (una reversión abre una nueva). |
| `changed` | `bool` | True cuando esta llamada cambió las marcas del grafo o el estado de cuarentena. |
| `template` | `bool` | True cuando el procedimiento es ahora una plantilla reutilizable (estable, casi siempre exitoso y no en cuarentena). |
| `folded_runs` | `int` | Filas del registro incorporadas al grafo por esta llamada. |
| `gate` | `Literal['none', 'undecided', 'accept', 'revert']` | Puerta de aceptación sobre una revisión pendiente: none (nada pendiente), undecided (aún no hay suficientes ejecuciones), accept, revert. |
| `gate_mode` | `str` | El modo de puerta utilizado (`sprt` o `margin`); "" cuando no había ninguna revisión pendiente. |
| `gate_llr` | `float` | sprt: razón de log-verosimilitud acumulada (un valor positivo favorece "la revisión empeoró las cosas"); el veredicto se emite cuando cruza un límite. |

| `gate_after` | `dict[str, int]` | {total, ok} de la revisión en prueba |
| `gate_cost_before` | `dict[str, float]` | Costo mediano de las ejecuciones exitosas por lado, y por qué una revisión que pasó la puerta de éxito se revirtió de todos modos ("cost"). |
| `gate_cost_after` | `dict[str, float]` | Costo mediano de las ejecuciones exitosas sobre la revisión en prueba. |
| `gate_reason` | `str` | `success` o `cost` en una reversión; "" en otro caso. |

| `fail_prone_steps` | `list[str]` | Contraste de resultados: pasos / transiciones desproporcionadamente presentes en ejecuciones fallidas (proporción de fallos >= tasa base de fallos del procedimiento + margen, con suficientes ejecuciones). |

| `quarantined` | `bool` | True cuando el procedimiento está eliminado por exceder el límite (véase `strike_limit`). |
| `retention` | `dict[str, float]` | Retención de éxito sobre el registro de trazas: pares de ejecuciones consecutivas cuya primera tuvo éxito, cuántas de las segundas lo tuvieron, y la tasa. |

Encuentra procedimientos cuyo campo `situation` es semánticamente el más cercano a la situación descrita por quien llama.

| `score` | `float` | Puntuación fusionada de la mejor coincidencia; 0 cuando nada coincidió. |

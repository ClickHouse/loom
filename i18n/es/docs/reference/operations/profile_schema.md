# Operaciones de `profile_schema`

Los campos de identidad (`org`, `namespace`, `agent`, `user_id`, `session_id`) se rellenan a partir del token y de la sesión MCP cuando el transporte puede hacerlo; en una llamada HTTP sin token en un servidor de un solo usuario, se usa la org de la instalación en todas las ops salvo `code.*` y `tracker.*` (que conservan la de su plano), y en [algunas ops](https://github.com/ClickHouse/loom/blob/main/docs/reference/http-api.md#request) también su espacio de nombres y su agente; consulta [identidades y espacios de nombres](https://github.com/ClickHouse/loom/blob/main/docs/concepts/identities-and-namespaces.md). ## `profile_schema.clear`

Borra el esquema: no se construye ni se reconstruye ningún perfil para el espacio de nombres, y las lecturas responden `no_schema`.

`POST /v1/profile_schema.clear` · MCP `loom_profile_schema_clear` · rol `admin` · idempotente · auditada · no aparece en el conjunto de herramientas `all` de MCP

| Campo de entrada | Tipo | Valor por defecto | Significado |
| --- | --- | --- | --- |
| `org` | `str` | obligatorio | El tenant (primer elemento de la tupla de identidad). |
| `namespace` | `str` | obligatorio | El espacio de nombres que la op lee o escribe. |

| Campo de salida | Tipo | Significado |
| --- | --- | --- |
| `found` | `bool` | False cuando el espacio de nombres no tiene esquema de perfil. |
| `json_schema` | `dict[str, Any]` | El esquema tal como lo definió el administrador, en el orden de sus claves; {} cuando no se encuentra. |
| `schema_sha256` | `str` | SHA-256 de las propiedades del esquema (no de sus títulos ni de su orden), que cada perfil nombra. |
| `updated_by` | `str` | El actor (`human:<subject>` o `process:<subject>`) que lo definió o borró por última vez; vacío cuando no se encuentra, o para un token limitado a un usuario. |
| `updated_at` | `datetime \| None` | Cuándo se definió o borró por última vez; None cuando no se encuentra. |

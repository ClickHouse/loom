# 벤치마크 범위

이 매트릭스는 Loom의 메모리, 지식, 코드 흐름 중 어느 부분에 재현 가능한 공개 측정이 있는지 보여 줍니다. 측정된 동작, 실행 가능한 하네스, 그리고 아직 공개된 품질 근거가 없는 제품 기능을 구분합니다.

<a id="status"></a>

## 상태

| 상태                | 의미                                                                                           |
| ------------------- | ---------------------------------------------------------------------------------------------- |
| **게시됨**          | 커밋된 결과 아티팩트, 모델 기록, 프로토콜, 제한 사항, 재현 명령이 존재합니다.                  |
| **부분 게시**       | 공개된 결과가 평가 질문의 일부를 측정하지만, 전체 흐름이나 대표적인 규모를 다루지는 않습니다.   |
| **하니스만 있음**   | 실행 가능한 프로토콜은 있지만, 공개 성능 주장을 뒷받침하는 커밋된 실제 프로바이더 측정이 없습니다. |
| **공개 측정 없음**  | 저장소에 이 질문에 대한 완전한 공개 프로토콜과 아티팩트가 없습니다. 제품 문서는 있을 수 있습니다. |

단위 테스트, 드라이 런, 가짜 프로바이더 게이트는 공개된 품질 결과로 인정하지 않습니다.
[결과 원장](https://github.com/ClickHouse/loom/blob/main/docs/benchmarks/results.md)은 공개된 수치의 출처이고, [하니스 목록](https://github.com/ClickHouse/loom/blob/main/bench/README.md)은 실행 가능한 프로토콜의 출처입니다.

## README에 포함할 내용

README에는 평가 결과가 측정하는 대상별로 묶은 여러 공개 벤치마크가 실려 있습니다.
이 매트릭스에서 **Published**로 표시되고, 표본이 해석하기에 충분히 크며, 결과가 일반화되지 않는 부분을 한 문장으로 분명히 설명할 수 있을 때만 해당 행을 README에 넣을 수 있습니다.

**Harness only** 또는 **No public measurement** 행은 README의 성능 주장으로 옮기지 마세요. 대신 이 매트릭스로 연결하세요. 하니스는 Loom을 측정할 수 있음을 보여 줄 뿐, Loom의 성능이 좋다는 것을 증명하지는 않습니다.

## 게시 백로그

아래 각 항목은 위 매트릭스의 평가 질문에 대응합니다.

- **쓰기 무결성과 정정:** 하나의 공개 대화 코퍼스에서 추출 정밀도, 거짓 메모리 비율, 대체(supersession) 및 오래된 답변 비율을 측정합니다.
- **지식 RAG:** 텍스트 문서에 대한 검색, 답변, 인용 품질을 측정하고, 이어서 PDF, CSV, 구조화된 텍스트를 위한 라이선스 형식 충실도 코퍼스를 다룹니다.
- **엔드투엔드 코드 에이전트 성과:** 누출을 통제한 패치 생성과 테스트 성공률을, Loom을 사용하지 않은 동일한 에이전트와 짝지어 비교합니다.
- **라이브 코드 이식성:** 기존 다국어(polyglot), SQL/셸, OSS 픽스처 전반에서 실제 provider로 측정합니다.
- **인덱스 비용과 최신성:** 저장소 크기별 콜드 및 증분 곡선을 측정하고, 하드웨어, ClickHouse 스토리지, 워커 리소스를 기록합니다.
- **용량과 안정성:** 테넌트 전반의 메모리/코드 혼합 워크로드를 측정하고, 이어서 워커, ClickHouse, 네트워크 장애 주입을 수행합니다.
- **안전성과 프라이버시:** 명명된 공격 결과는 별도로 게시하며, 일반적인 안전성 점수 하나로 합치지 않습니다.

새로운 결과는 모두 [결과 추가하기](https://github.com/ClickHouse/loom/blob/main/docs/benchmarks/results.md#adding-a-result)를 따릅니다. 원본 아티팩트를 커밋하고, 사용한 모든 모델과 서버 빌드를 기록하고, 데이터셋 라이선스를 명시하고, 정확한 명령을 포함하고, 실패와 부정적인 발견을 보고하고, 불확실성 또는 질문 하나의 변동 크기를 추가합니다.

# 정의 초안

갭 초안에는 `knowledge_gaps_enabled`가, 쿼리 기록에는 `knowledge_query_history_enabled`가 필요합니다. 두 경로 모두 모델이 작성한 정의를 관리자 검토 대기열에 넣습니다.
모델은 정의를 직접 게시하지 않습니다. 이 페이지는 근거, 비공개 후보, 검토를 설명하며, 검색의 기록과 그룹화는 [지식 갭](https://github.com/ClickHouse/loom/blob/main/docs/architecture/knowledge-gaps.md)에서 설명합니다.

## 근거와 접근

라이브러리의 **Draft definition** 동작은 `knowledge.gaps.draft`를 호출합니다. 이 동작은 현재 7일 미스 구간을 기준으로 갭의 질문을 다시 읽고, 각 질문마다 서로 다른 질문자가 최소 `knowledge_gaps_min_askers`명 있어야 합니다. 정규화된 질문만 모델에 보냅니다. 수집 동의는 캐시 없이 읽으며, 동의를 확인할 수 없으면 초안을 거부합니다. 작업 중에 임계값이 바뀌거나 사용자 삭제가 일어나면 근거가 무효화되고, 해당 시도의 후보 버전은 제거됩니다.

`knowledge.query_history.add`, `.list`, `.remove`에는 네임스페이스 관리자 권한이 필요합니다. 라이브러리에서 **Query history**를 열면 소스 목록과 연결 양식이 나타납니다. 등록 정보에는 이름, 호스트, 포트, TLS 선택, 읽기 전용 계정, 데이터베이스 허용 목록, 선택 사항인 클러스터가 있습니다. 비밀번호는 저장 시 봉인되며 다시 반환되지 않습니다. 연결은 트래커의 호스트 검사, 고정된 주소, 읽기 전용 권한 검토를 재사용합니다. 클러스터에는 `REMOTE`도 필요합니다. 등록을 제거하면 이후 턴은 중단되지만 기존 초안이나 정의는 삭제되지 않습니다. 운영자가 쿼리 기록을 비활성화해도 연결 해제는 계속 사용할 수 있습니다.

워커는 완료된 초기 `SELECT` 쿼리 중 데이터베이스 목록이 비어 있지 않고 전부 등록의 허용 목록에 속하는 것만 읽습니다. 이름이 지정된 클러스터는 `clusterAllReplicas`를 사용하고, 그렇지 않으면 연결된 노드만 읽습니다. 그룹은 `normalized_query_hash`와 `normalizedQueryHashKeepNames`로 만들며, 서로 다른 `initial_user` 계정의 수와 최근성 순으로 정렬합니다. 두 번째 해시는 번호가 다른 테이블 이름을 구분하면서도 공백이나 리터럴 차이로 그룹이 갈라지지 않게 합니다. `normalizeQueryKeepNames`는 주석을 제거하고 리터럴을 대체하되 식별자는 유지합니다. 모델에는 이 정규화된 SQL만 전달됩니다.

그룹을 뒷받침하는 계정은 최소 `knowledge_query_history_min_users`개여야 하며 3개 미만일 수 없습니다. 계정은 사람과 같지 않습니다. 공유 계정 하나는 한 번만 세고, 한 사람의 여러 계정은 각각 셉니다. 이 하한은 익명성을 보장하지 않습니다. 실행 중에 임계값을 올리거나 기록 구간을 바꾸면 진행 중인 결과가 무효화됩니다. 소스 제거, 소스 UUID 변경, 기능 비활성화, 네임스페이스 삭제도 마찬가지로 결과를 무효화합니다.

후보는 `source_kind = knowledge_gap` 또는 `query_history`를 사용합니다. 모델이 작성한 텍스트와 쿼리 기록 SQL은 `learnings.list`, 품질 집계, 명시적·추론된 계보 모두에서 네임스페이스 관리자에게만 비공개로 유지됩니다. 필터링은 조직 전체 품질 조회를 포함해 페이지 나누기와 집계보다 먼저 수행됩니다. 읽기 범위가 좁혀진 토큰은 두 동작 접두사 중 어느 것도 호출할 수 없습니다.

## 한 번의 모델 시도

후보 ID는 조직, 네임스페이스, 종류, 근거 리소스에서 파생됩니다. 갭은 갭 ID를, 쿼리 기록은 등록 UUID와 두 쿼리 해시를 사용합니다. 짧은 후보 리스를 잡고 대기 중인 클레임을 저장한 다음, 모델 호출을 위해 리스를 해제합니다. 동시 요청과 이후 요청은 결정, 모델 오류, 잘못된 결과, 크래시 이후에도 그 후보 ID를 반환합니다. 이런 실패가 일어나면 대기 중인 클레임이 남고, 그 근거 설명은 관리자에게 이를 거부하고 직접 작성하라고 안내합니다. 생성 전에 정책 보류가 걸리면 사용되지 않은 클레임의 버전만 제거되므로, 허용될 때 재시도할 수 있습니다.

조직의 모델 호출 스위치와 네임스페이스 일일 한도는 작업을 클레임하기 전에 확인하며, 한도를 읽을 수 없으면 작업을 거부합니다. 각 시도는 크기가 제한된 JSON 완성 한 번만 허용합니다. 결과는 용어, 별칭, 본문, 테이블/컬럼 목록 크기를 검증합니다. `rests_on`의 갭 출처에는 갭 ID와 모델의 테이블/컬럼 목록이 담깁니다. 대상이 되는 질문은 모델 입력에만 전달되며 애플리케이션이 후보에 복사하지 않습니다. 다만 모델이 초안 텍스트에서 질문을 반복할 수 있습니다. 생성 후에는 원본 질문에 대한 사용자 삭제가 일어나도 초안과 갭 ID가 남아 있을 수 있습니다. 쿼리 기록 출처에는 정규화된 SQL과 모델의 테이블/컬럼 목록이 보존됩니다. 마지막 후보 리스가 상태를 다시 읽으므로, 완료 처리가 거부를 덮어쓰거나 지워진 텍스트를 복원할 수 없습니다. 근거 펜스는 모델 작업 전후와 삽입 후에 실행됩니다.

워커는 소스, 그룹, 시도, 쿼리 바이트, 행, 메모리, 실행 시간에 한도를 둡니다. 패스 예산의 절반이 지나면 더 이상 그룹을 시작하지 않으며, 마지막 소스의 UUID를 해당 턴 전에 저장하므로 실패하는 소스가 순환을 막지 않습니다. 고정 크기 UUID는 소스 이름이 저장된 커서에 남지 않게도 합니다. 연결 실패에는 소스별로 제한된 서킷 브레이커를 사용합니다. 워커 비용 이벤트는 네임스페이스 귀속을 유지합니다.

## 검토와 게시

`learnings.review`는 이러한 후보를 대상이 `memory`일 때만 수락합니다. 쓰기 전에 플릿 기능, 민감도, 공유 정의 상한, 이름 충돌을 확인합니다. 초안은 대소문자 등을 정규화한 용어나 별칭이 자신의 용어와 일치하는 활성 공유 정의를 수정하며, 일치 대상이 모호하면 거부합니다. 새 용어는 클레임과 함께 저장된 무작위 `definition/` 키를 사용합니다. 쓰기 전에 공유 행을 다시 읽으므로, 동시에 일어난 이름 변경이 쓰기를 다른 용어로 돌릴 수 없습니다.

검토는 `memory.set`을 통해 네임스페이스 전체에 적용되는 파생 정의를 쓰며, 만료와 유효 기간 제한을 지웁니다. 정확히 일치하고 활성이며 만료되지 않은 헤드는 고정되었거나 잠겨 있어도 쓸 필요가 없습니다. 값이 바뀐 경우 고정되었거나 잠긴 헤드에는 거부됩니다. 수정하려면 현재 원본 텍스트가 공유 사본과 일치해야 하며, 그 사이 작성자가 편집했다면 거부합니다. 보존된 만료 헤드는 해시를 사용해 조건부로 다시 쓰고, 헤드가 없으면 `if_match_sha256="absent"`를 사용합니다. 조건부 호출자는 키 기준으로 직렬화되며, 일반적인 동시 ClickHouse 쓰기는 버전으로 해소됩니다. 이러한 검사로 쓰기와 승격이 원자적이 되지는 않습니다.

검토는 승인된 정규 값 해시와 함께 `memory.promote`를 호출합니다. 서버가 내부적으로 후보 출처를 제공하고 인증된 행위자를 기록합니다. 클라이언트는 신뢰할 수 있는 출처를 제공하거나 `approver`로 결정 행위자를 선택할 수 없습니다. 승격은 정규화된 SQL을 포함한 정의 전체를 네임스페이스의 독자에게 게시하므로, 관리자는 모든 독자를 대상으로 그 텍스트를 승인하는 셈입니다.

쓰기가 커밋된 뒤 게시나 승격이 실패하면 일반적인 네임스페이스 전체 정의와 대기 중인 후보가 남습니다. 일반 검색은 그 행을 읽을 수 있습니다. 재시도는 변경되지 않은 정확한 헤드를 다시 쓰지 않고 승격합니다. 후보를 거부해도 원본 행은 그대로 유지됩니다. 자동 되돌리기는 없습니다. 되돌리면 이후 작성자의 동일 텍스트 메타데이터 수정을 덮어쓸 수 있기 때문입니다. 관리자는 메모리 기록과 쓰기 동작으로 의도한 텍스트를 복원하거나 특정 버전을 명시적으로 삭제할 수 있습니다.

## 삭제, 감사, 업그레이드

네임스페이스 삭제는 `query_history_sources.delete`를 통해 `loom.query_history_sources`를 삭제합니다. 등록에는 설정과 봉인된 자격 증명이 있으므로, 메모리 콘텐츠 census 행 없이 이 단계로 분류됩니다. 후보는 learnings 대기열의 삭제 범위를 따릅니다. 과거 정의의 redact는 정규 텍스트 해시나 redact된 버전의 후보 태그가 일치하는 비공개 후보도 모든 후보 버전에 걸쳐 지웁니다. 이는 검토 리스를 사용하고, 빈 텍스트에 대한 이후 검토를 거부하며, redact된 텍스트를 여전히 가진 라이브 헤드는 보존합니다.

검토 감사는 인증된 결정 행위자와 후보를 식별합니다. 내부 `memory.set`과 `memory.promote`는 각자 감사 이벤트를 내보내며, 승격 이벤트는 `memory.lineage`가 따라가는 감사 요청 ID이기도 합니다. 소스 변경은 범위가 지정된 등록 이름을 감사하며 비밀번호는 절대 기록하지 않습니다.

비공개 종류의 생성과 승격에는 모든 라이브 서버와 워커 하트비트가 등록 마이그레이션을 알려야 합니다. 플릿 상태가 없거나 읽을 수 없으면 안전하게 실패합니다. 두 초안 경로 중 하나를 활성화하기 전에 마이그레이션을 적용하고 모든 서버와 워커를 업그레이드하세요. 이전 빌드나 알 수 없는 빌드가 서비스 중이면 두 경로를 모두 비활성화해 두세요. 이전 빌드는 비공개 후보를 필터링하지 않고 등록도 삭제하지 않습니다. 플릿 검사만으로는 롤백을 보호할 수 없습니다. 이전 하트비트가 나타나기 전에 요청이 검사를 통과할 수 있기 때문입니다.

롤백은 이전 리더를 시작하기 전에 유지보수 창에서 수행해야 합니다.

1. `knowledge_gaps_enabled`와 `knowledge_query_history_enabled`를 모두 비활성화합니다. 새 비공개 초안 작성, 검토, 소스 등록 요청과 쿼리 기록 워커 턴을 중단합니다. 대기 중인 작업과 승인된 모든 모델 호출, 검토, 등록, 제거를 정지시킵니다. 플래그를 비활성화해도 기존 요청이나 검토는 취소되지 않습니다.
2. 이러한 작업이 끝나거나 종료되도록 둔 다음, 불확실한 서버 전송과 유지 중인 작성자 리스를 각 한도 안에서 정리합니다. 승인된 작업이 아직 후보, 결정, 등록을 쓸 수 있는 동안에는 테이블을 정리하지 마세요.
3. 유지보수를 위해 지원하는 빌드만 실행한 상태에서 `loom.learnings_queue`의 `knowledge_gap`과 `query_history` 후보의 모든 버전과 `loom.query_history_sources`의 모든 등록을 제거합니다. 삭제가 끝날 때까지 기다리고, 리더가 사용할 수 있는 모든 스토리지 레플리카에서 둘 다 없는지 확인합니다. 일반 후보와 게시된 정의는 보존합니다. 그런 다음에야 이전 리더를 시작하세요.

다운그레이드 내내 비공개 생성기를 비활성화 상태로 유지하세요. 서비스 중인 모든 프로세스가 등록 마이그레이션을 지원한 뒤에만 다시 활성화합니다. 관리형 메모리와 공유 행에는 기존 업그레이드 규칙이 그대로 적용됩니다.

<a id="source-entry-points"></a>

## 소스 진입점

- `server/memory/app/definition_drafts.py`: 지속되는 클레임과 제한된 생성.
- `server/memory/app/definition_review.py`: 플릿 게이트, 승격, 후보 redact.
- `server/knowledge/app/gap_drafts.py`: 현재 갭 적격성과 동의.
- `server/knowledge/app/query_history_sources.py`: 등록과 자격 증명 검사.
- `server/knowledge/store/query_history_remote.py`: 읽기 전용 그룹화된 쿼리 로그 읽기.
- `server/knowledge/workers/query_history.py`: 제한된 소스 순환.

<a id="invariants"></a>

## 불변 조건

- 관리자만 비공개 후보를 읽거나 검토를 통해 게시할 수 있습니다.
- 어떤 모델 완성도 후보 결정을 대체하거나 삭제된 근거를 되살리지 못합니다.
- 소스 등록은 네임스페이스 삭제 이후에도 남아 초안을 계속 생성할 수 없습니다.
- 거부되거나 중단된 승격은 작성자의 행을 되돌리지 않습니다.

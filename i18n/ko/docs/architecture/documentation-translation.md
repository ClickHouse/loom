# 문서 번역 요청

번역 생성기는 준비된 영어 텍스트를 크기가 제한된 요청으로 나누고, 조립한 번역을 파일에 쓰기 전에 검사합니다. 영어가 기준 원본으로 유지됩니다.

<a id="request-planning"></a>

## 요청 계획

`english_requests`는 페이지 전체에 걸친 하나의 카운터로 제목 앵커를 할당합니다. 안전한 2단계 제목 경계에서 나누는 것을 우선하며, 크기가 큰 섹션은 최대 16 KiB의 소스 조각으로 묶습니다. 이 조각들을 줄바꿈으로 이으면 앵커가 붙은 영어 원문이 정확히 복원됩니다.

계획기는 목록 항목, 코드 블록, 표 행에 대해 CommonMark 토큰 소스 범위를 사용합니다. 펜스 코드와 들여쓰기 코드, 인라인 코드, 완전한 HTML 요소, 주석은 한 덩어리로 유지됩니다. 표 헤더는 구분선과 함께 유지됩니다. 나눌 수 없는 단위가 너무 크면 페이지의 첫 모델 호출 전에 거부됩니다. 비용 추정은 번역과 동일한 요청 목록을 사용합니다.

사이트의 목록 확장은 순서 있는 항목을 포함해 두 칸 들여쓴 이어지는 줄을 허용합니다. 이 파서에는 소스 맵이 없으므로, CommonMark 범위와 함께 들여쓰기 스캔으로 이러한 항목을 보호합니다. 두 방언의 항목 모두 분할되지 않습니다.

일부 사이트 확장 표는 CommonMark에서는 들여쓰기 코드입니다. 해당 코드 범위는 분할되지 않으므로, 이런 모호성이 있는 큰 블록은 제공자 승인 전에 거부됩니다. 표를 확장 컨테이너 밖으로 옮기면 영어 원문에서 이 모호성이 해소됩니다.

<a id="original-unit-reconciliation"></a>

## 원본 단위 조정

`reconcile_completed_units`는 영어 원문이 수정되어도 완료된 요청을 유지하기 위한 순수 계획 API입니다. 이 API는 이전 및 현재 `PreparedSource` 컨테이너와, 다이제스트가 포함된 완전한 `OriginalUnit` 매니페스트를 받습니다. 두 컨테이너에는 준비된 링크와 페이지 전체 앵커가 포함됩니다. 모든 원본 범위와 소스 해시는 이전 컨테이너와 일치해야 하며, 범위 사이의 간격에는 빈 문자열이나 LF만 있어야 합니다. 매니페스트 다이제스트는 선택된 각 응답 참조를 포함한 이 메타데이터를 묶어 보증합니다.

호출자는 완전한 원본 계획과 완료 상태를 자신의 요청 원장, 캐시, 선택된 응답 영수증과 대조해 인증합니다. 캐시 파일이 없다는 사실만으로는 아무것도 증명되지 않습니다. `reply_ref=None`인 원본 단위는 불확실한 시도가 해결된 뒤 완료된 응답이 없음을 명시적으로 증명합니다. 확정된 오류가 있는 완료된 응답은 해당 참조와 `UnitFault`를 유지하며, 참조를 생략해 미완료 작업으로 바꿀 수 없습니다. 호출자는 소스 버전 전반에 걸쳐 로케일/소스 쌍 전체에 대한 거부 목록도 제공합니다.

계획은 현재의 파서 안전 경계에서 고유하고 단조로우며 바이트 단위로 동일한 완료 단위 전체만 유지합니다. 페이로드는 마지막 줄바꿈을 자신이 가질 수도 있고, 조립 단계에 LF 하나를 남길 수도 있으며, 연속된 페이로드는 연속 상태를 유지합니다. 각 처리 결과(disposition)에는 현재 `SourceContext`, 원본 출처, 오류 식별자, 정확한 구분자가 담깁니다. 제공자 호출 없이 재사용하는 완료 단위는 요청 크기 제한을 넘을 수 있습니다. 미완료 간격과 새로 삽입된 영어는 유지되는 범위 밖에서 제한된 크기의 계획기를 사용합니다. `chunks.split`은 `source_context`를 받으므로, 헤더가 없는 표 조각도 현재 표 전체의 행 경계를 사용할 수 있습니다.

처리 결과는 재사용, 동일 입력 수정, 입력 변경, 미완료 작업으로 구분됩니다. 하나의 원본 단위에 영향을 주는 소스 수정과 오류는 하나의 입력 변경 처리 결과를 공유합니다. 반복된 후보, 겹치거나 순서가 바뀐 범위, 안전하지 않은 경계, 알 수 없는 오류, 쌍 거부는 충돌로 반환됩니다. 일치하지 않는 여러 원본 단위 중에서 변경된 완료 단위가 있으면 대응하는 경계가 입증되어야 하며, 계획기는 분할을 추측하지 않습니다. 완료된 페이지 전체 단위의 교체는 지원되지 않습니다. 페이지 전체를 그대로 재사용하는 것은 여전히 가능하지만, 이 API가 변경된 페이지의 모든 대응 관계를 해결하지는 않습니다.

`chunks.split`과 `reconcile_completed_units`는 모두 `bounded_new_request_bytes`를 받으며, 불리언을 제외한 1에서 16384 사이의 정수여야 합니다. 기본값은 16 KiB 경계를 유지합니다. 이 제한은 입력 변경 수정과 동일 입력 수정을 포함한 모든 예정 요청에 적용됩니다. 재사용되는 완료 단위는 이 제한을 넘더라도 통째로 유지됩니다. 제한에 맞출 수 없는 변경되었거나 오류가 있는 완료 단위는 분할되지 않고 충돌로 반환됩니다.

더 낮은 제한은 잘린 응답 이후의 미완료 작업을 더 잘게 나눌 수 있습니다. 호출자는 확정된 요청, 소스 범위, 응답, 사용량, 모든 완료 및 거부 상태, 이후의 원장 항목을 인증합니다. 실행 패킷은 선택된 제한과 정확한 현재 계획(대응 범위와 유지되는 완료 참조 포함)을 묶어 보증합니다. 제한만으로는 이 증거가 성립하지 않으며, 보류를 해제하거나 호출을 승인하지도 않습니다. 잘린 응답의 앞부분은 완료된 단위가 아니며, 입력이 작아진다고 해서 응답이 온전히 완료된다는 보장은 없습니다.

`translate_text`는 입력 변경 제약을 위해 현재 소스 컨텍스트와 함께 신뢰할 수 있는 `initial_feedback`을 받습니다. `request_system`은 이 피드백을 제공자에게 보내는 정규 SYSTEM에 그대로 포함하므로, 실제 요청 페이로드가 제약을 묶어 보증합니다. 피드백은 출력 가능한 ASCII와 LF로 이루어진 4096바이트 이내여야 하며, 피드백이 비어 있으면 기본 SYSTEM이 유지됩니다. 첫 메시지에는 현재 영어 원문만 담깁니다. 이전 입력에 대한 어시스턴트 응답은 재전송되지 않으며, 기계적 재시도에는 현재 입력에 대해 반환된 응답만 사용할 수 있습니다. 잘못된 피드백이나 일치하지 않는 소스 컨텍스트는 비용 지출이나 제공자 호출 전에 거부됩니다.

조정 계획은 응답을 확정하거나, 제공자 호출을 승인하거나, 출력을 쓰지 않습니다. 소비자는 확정된 응답을 인증하고 현재 컨텍스트에 맞게 검증한 다음, 조립된 전체 페이지를 검증합니다. 콘텐츠 불변 조건과 두 표 방언의 검사도 그대로 적용됩니다. 게시하려면 현재 영어 원문을 기준으로 한 의미 및 언어 완전성 검토도 필요하며, 구조 검사를 통과했다고 해서 확정된 오류나 거부가 해소되지는 않습니다.

<a id="assembled-validation"></a>

## 조립 후 검증

조립된 페이지는 출력 디렉터리나 파일이 만들어지기 전에 기존 콘텐츠 불변 조건과 표 검사를 통과해야 합니다. 표 검사는 문서 사이트의 Markdown 파서와 표 확장을 켠 CommonMark를 모두 사용하며, 두 파서의 컨테이너 규칙은 서로 다릅니다. 검사는 표 그룹, 행, 셀, 정렬, 셀이 비어 있는지 여부를 유지합니다. 사이트의 목록, admonition, 코드 확장도 검사에 포함됩니다. 셀 텍스트는 직렬화와 원시 HTML 복원 이후에 측정하므로, 빈 마크업이 누락된 텍스트를 가릴 수 없고 이스케이프된 리터럴 태그는 텍스트로 남습니다.

파서 패키지는 번역 요구 사항과 개발용 extra에 고정되어 있습니다. 사이트 파서의 고정 버전은 문서 빌더와 일치합니다. 소스 바이트 제한이 번역된 응답이 출력 토큰 제한 안에 들어간다는 것을 보장하지는 않습니다. 잘린 응답은 계속 실패로 처리되며, 구조 검사는 번역 품질이나 문장의 완전성을 보증하지 않습니다.

<a id="source-spelling-contracts"></a>

## 소스 철자 규약

레이블 검증은 소스 철자와 일반 설명을 구분합니다. 소스별 이름 선언은 정확한 제품 및 프로젝트 표기 구간을 보호합니다. 파일 이름 레이블은 소스 링크 대상의 추적되는 저장소 파일과 일치해야 하며, 관례적인 `README` 레이블은 `.md` 접미사를 생략할 수 있습니다. 작업 필드 선언은 반환되는 문자열 어휘와 문서화된 하나의 필드 공식을 보호합니다. 설명 전체가 따옴표로 묶인 식별자 대안으로 이루어진 문자열 타입 필드도 리터럴 값을 선언합니다. 따옴표, 대문자 표기, 파일 이름처럼 보이는 철자만으로는 예외가 인정되지 않습니다.

이러한 선언에는 소스 근거가 필요합니다. 패키지 또는 프로젝트 식별자, 명시적인 용어 정의, 실제 파일 대상, 또는 해당 작업의 와이어 규약이 그 근거입니다. 이러한 소스 선언을 변경할 때는 증명과 이에 해당하는 집중 회귀 테스트 사례를 확인해야 합니다. 보호되는 구간 주변의 일반적인 수식어에는 계속 레이블 검증이 적용됩니다.

기존의 사이트 파서와 CommonMark 파서가 이스케이프된 파이프와 인라인 코드 파이프를 포함한 표 셀을 제공합니다. 각 제한된 요청은 주변 텍스트를 제공자에게 보내지 않고 완전한 영어 컨테이너 안에서 검사됩니다. 소스 맵이 없는 사이트 전용 셀은 페이지 조립 시 검사됩니다. 재시도, 조립, 저장된 페이지 검사는 같은 규칙을 공유합니다. 보호되는 구간은 철자, 등장 순서, 소스 레이블 또는 필드를 유지해야 합니다. 이는 한정된 소스 규약이며, 언어 분류기도 의미 검토도 아닙니다.

<a id="invariants"></a>

## 불변 조건

- 제공자에게 보내는 모든 소스 조각은 제한 이내에 머뭅니다. 모든 소스 바이트와 페이지 전체 앵커는 조립 후에도 유지됩니다. 재사용되는 완료 단위는 페이로드 전체를 유지합니다.
- 나눌 수 없는 단위는 제공자 승인 전에 거부됩니다.
- 제공자 설정, 출력 토큰 제한, 재시도, 누적 비용 검사는 페이지를 어떻게 나누었는지와 무관하게 모든 요청에 각각 적용됩니다.
- 출력은 조립 후 검증이 성공한 뒤에만 기록됩니다.

<a id="source-entry-points"></a>

## 소스 진입점

- `scripts/i18n/translate.py`: `english_requests`, `request_chars`, `translate_page`.
- `scripts/i18n/translate.py`: `request_system`, `translate_text`, 초기 피드백.
- `scripts/i18n/reconcile.py`: `reconcile_completed_units`, `OriginalUnit`, 매니페스트 바인딩.
- `scripts/i18n/chunks.py`: 보호 범위, 컨텍스트 기반 소스 분할, 파싱된 표 셀.
- `scripts/i18n/context.py`: 소스 철자 선언, 잔여 레이블 투영.
- `scripts/i18n/requirements.in`: 번역 런타임 의존성.

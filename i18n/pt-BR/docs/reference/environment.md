# Referência de variáveis de ambiente

Quase tudo o que configura o Loom é um campo de settings: a variável de ambiente `LOOM_<FIELD>` de um campo em `server.settings.Settings`, listada com seu valor padrão e seu significado na [referência de configuração](https://github.com/ClickHouse/loom/blob/main/docs/reference/configuration.md) gerada. Esta página cobre o restante: as variáveis lidas diretamente com `os.environ` (ou um `${VAR}` do shell) pelo servidor, pela CLI, pelos SDKs, pelos plugins, pela imagem de contêiner, pelos arquivos compose e pelos scripts de operação. As variáveis `LOOM_*` estão listadas em `NON_SETTINGS_ENV` (`server/settings/_env.py`) ou, no caso de uma família como os segredos de assinatura de webhook, em `NON_SETTINGS_ENV_PREFIXES`, e o aviso de variável desconhecida do servidor ignora essas variáveis; `tests/unit/test_environment_reference.py` mantém essas listas e esta página sincronizadas.

## Imagem de contêiner e uvicorn

Lidas por `scripts/serve.sh`, o comando da imagem, que inicia o uvicorn. Ele as
obtém apenas do seu ambiente, não de `.env` nem de `LOOM_ENV_FILE` (o `env_file:` do compose
as define no ambiente), exceto os campos de configuração
`LOOM_WEB_WORKERS`, `LOOM_TRUSTED_PROXIES` e `LOOM_RUNTIME_DIR`, que ele
resolve conforme o servidor os carrega: o ambiente, depois o arquivo de env, depois o
[arquivo de configurações](https://github.com/ClickHouse/loom/blob/main/docs/reference/configuration.md). As variáveis `UVICORN_<OPTION>` do próprio uvicorn não
são lidas: a camada web se recusa a iniciar enquanto houver uma definida para uma opção do uvicorn que
`scripts/serve.sh` não repassa:

| Variável                   | Padrão               | Significado                                                                                                                                                                                                                                                                                                                                            |
| -------------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `PORT`                     | `7777`               | A porta em que o uvicorn faz o bind dentro do contêiner.                                                                                                                                                                                                                                                                                               |
| `LOOM_LISTEN_HOST`         | `127.0.0.1`          | `uvicorn --host`: o endereço em que ele escuta. A imagem define `0.0.0.0`; `LOOM_BIND_HOST` continua sendo o endereço lido pelas verificações de inicialização, e `scripts/serve.sh` o define como um endereço de escuta não loopback quando o ambiente não o define (sobrescrevendo um valor do arquivo de env ou do arquivo de configurações).       |
| `LOOM_WEB_WORKERS`         | um por CPU, até 8    | `uvicorn --workers`. Se não definido, um por CPU que o contêiner pode usar (seu cpuset, reduzido por uma cota de CPU), no máximo um por GiB de memória e no máximo 8. Os arquivos compose o definem, a menos que `.env` indique uma contagem: 2 em `deploy/standalone` e na stack de desenvolvimento, 1 nas stacks cloud e colour. Também é um campo de configurações, pelo qual o limitador de taxa divide os orçamentos. |
| `LOOM_UVICORN_LOOP`        | `asyncio`            | `uvicorn --loop`: `asyncio`, `auto` ou `uvloop`. O uvloop faz fork do processo inteiro a cada git spawn, o que trava seu loop.                                                                                                                                                                                                                         |
| `LOOM_TRUSTED_PROXIES`     | `127.0.0.1`          | `uvicorn --forwarded-allow-ips`: os peers cujos `X-Forwarded-For`/`-Proto` são aplicados.                                                                                                                                                                                                                                                              |
| `LOOM_GRACEFUL_SHUTDOWN_S` | `10`                 | `uvicorn --timeout-graceful-shutdown`: por quanto tempo um processo em parada drena as requisições.                                                                                                                                                                                                                                                    |
| `LOOM_KEEP_ALIVE_S`        | `5`                  | `uvicorn --timeout-keep-alive`: por quanto tempo uma conexão ociosa permanece aberta. Atrás de um balanceador de carga que reutiliza conexões, deve ser maior que o timeout de ociosidade dele.                                                                                                                                                         |

Argumento de build: `LOOM_BUILD_COMMIT` (incorporado à imagem como `LOOM_BUILD_COMMIT`,
informado como `build_commit`). A imagem sempre inclui o embedder local de CPU e seu
modelo padrão, e define `LOOM_LOCAL_EMBEDDING_MODEL_DIR=/app/models`. Os demais
`ARG`s fixam versões de toolchain e checksums dos indexadores da camada do compilador
(`GO_VERSION`, `NODE_VERSION`, `SCIP_GO_VERSION`, `SCIP_CLANG_VERSION`, seus
valores `*_SHA256*` e `LLVM_SIGNER_FPR`, a impressão digital da chave de assinatura do LLVM);
`scripts/install-code-toolchains.sh` fixa as ferramentas que instala com o npm
(scip-typescript, scip-python e os gerenciadores de pacotes).

Quando passada ao instalador, `LOOM_VERSION` instala a release que ela nomeia. Sem ela, o
`install.sh` de uma release instala a própria release e a cópia do repositório instala `latest`;
uma release mais antiga sobre uma instalação mais nova é recusada, a menos que `LOOM_VERSION`
a nomeie (fixe o ClickHouse primeiro:
[como fazer downgrade de uma instalação feita pelo instalador](https://github.com/ClickHouse/loom/blob/main/docs/operations/upgrades.md#downgrading-an-installer-install)).

As demais referências `${LOOM_*}` nos arquivos compose são campos de configuração com um
padrão definido no nível do compose, além das variáveis do uvicorn acima. O instalador mantém no
`.env`, quando informados, os dois repositórios de imagem (`LOOM_IMAGE_REPOSITORY`,
`LOOM_EXTRACTOR_IMAGE_REPOSITORY`), a tag, a porta, o host de bind e `LOOM_CLICKHOUSE_IMAGE`; o
[guia de início rápido](../getting-started/quickstart.md) descreve o que o `.env` padrão define.
